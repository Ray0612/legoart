# 项目需求规格说明书：乐高画作智能转换器 (LEGO Art Converter)

**版本**：V1.0
**日期**：2026-09-03
**开源协议**：GNU GPL v3 / MIT (免费，禁止商用)
**项目形态**：Windows 本地客户端 + Web 网页端（私有化部署或自建服务器）

---

## 1. 项目概述
本项目旨在开发一款工具，允许用户上传任意电子图片（如星空等油画），通过算法自动生成一份“乐高积木拼搭方案”。方案支持两种核心模式（理想拼搭 / 库存约束拼搭），并输出专业的 PDF 说明书及 Excel 物料清单。项目将集成开源计算机视觉库，并支持本地计算与云端计算两种算力模式。

---

## 2. 核心功能需求 (Functional Requirements)

### 2.1 输入源 (Input)
- **格式支持**：接受常见图片格式（JPG, PNG, BMP, WEBP 等，其他格式则进行转换）。
- **图片形式**：图片形式又用户选择“油画”或“照片”，两种模式需要针对性优化。
- **算法双模式**（用户可选）：
  - **色块化模式**：提取画面主色调，将图像转化为清晰的乐高马赛克色块（类似官方艺术套装）。
  - **纹理保留模式**：通过边缘检测增强算法，保留笔触纹理细节（颗粒数会相应增加，适合抽象画）。

### 2.2 尺寸与颗粒度 (Sizing)
- **尺寸输入**：用户自由指定目标画作的长 x 宽（单位：乐高颗粒数 Studs，需要给用户预览cm的长度）。用户也可以自己选择单位例如选择了cm后则匹配对应最接近的颗粒数。
- **细节等级**：用户可拖动滑块选择“基础（大颗粒）”至“精细（小颗粒）”，程序将根据此参数自动换算所需的底板尺寸及总颗粒预估量。
- **性能约束**：生成方案的计算时间**最长不超过 60 秒**。若超过，系统将提示用户切换至云端计算或降低颗粒度。

### 2.3 拼搭逻辑与颜色匹配 (Core Logic)
本工具提供两种独立的“生成模式”供用户切换：

#### 模式 A：理想购物车模式 (Ideal Mode)
- **逻辑**：忽略用户现有库存，纯粹依据 CIEDE2000 色差公式，从乐高官方全量色库中选取最接近原画的颜色。
- **输出**：生成一份“必须购买”的零件购物清单。

#### 模式 B：库存约束拼搭模式 (Inventory-Constrained Mode)
- **逻辑**：加载用户现有积木库存（颜色 + 数量），优先使用库存，缺货时触发三重处理策略。
- **缺货处理策略（三选一）**：
  1. **近似替代**：使用库存中最近似的颜色替代（牺牲色彩精度）。
  2. **生成缺件清单**：保留原色方案，单独列出缺失的零件编号及数量，供用户去 BrickLink 等网站下单。
  3. **极限拼搭**：强制仅使用现有库存填充，无法匹配的位置留空或使用黑白灰填充（仅输出可完成的部分）。

### 2.4 用户积木库存管理 (Inventory Management)
- **录入方式**：支持**批量入库**。
  - 用户可拍摄多张散落积木的照片上传至程序。
  - **识别范围**：利用视觉模型（如 YOLO）识别图片中的**颜色**（必选），**零件形态（如 2x4 砖）由用户在下拉框中手动确认**（可选，以降低识别难度和误报）。
- **库存扣减**：每次生成拼搭方案并确认“开始拼搭”后，系统自动从总库存中扣减对应颜色及数量的零件。**不涉及“拆除之前的作品”逻辑**。

### 2.5 输出产物 (Outputs)
点击“生成方案”后，系统需同时产出以下文件（存放于用户指定目录）：

1. **PDF 拼搭说明书**：
   - 包含成品预览图与物料清单。
   - **分层 6 视图**：针对每一层（Layer），提供正、背、左、右、俯、仰六个角度的搭建示意图（可使用矢量线条图或彩色网格图）。从底层开始给予用户指导。
2. **Excel 物料清单 (BOM)**：
   - 字段必须包含：**颜色名称/色号、零件形态（如 Plate 2x4）、单层用量、总用量**。

## 3. 技术架构与部署 (Technical Stack)

### 3.1 平台支持
- **Windows 客户端**：使用 C# + .NET MAUI 或 Python + PyQt6（推荐后者，便于复用 AI 库）。
- **Web 网页端**：React/Vue 前端 + Flask/FastAPI 后端（Python）。

### 3.2 计算模式
- **本地计算（默认）**：利用用户本地 CPU/GPU 运行轻量级颜色匹配算法。适合 2000 颗粒以下的方案。
- **云端计算（后续扩展）**：当用户选择高精度或大尺寸（如 10000+ 颗粒）时，将图片上传至自建服务器，由高性能集群运算后返回 JSON 方案数据。

---

## 4. 数据与接口设计 (Data Structure)

### 4.1 乐高颜色映射表
- 基于开源项目 `legocolors` 构建官方颜色 RGB 对照表。
- 形态库：需内置常见乐高砖块形态列表（供用户录入时点选）。

### 4.2 本地数据库 (SQLite)
- **表 `inventory`**：`id`, `color_code` (VARCHAR), `part_shape` (VARCHAR), `quantity` (INT)。
- **表 `project_history`**：记录每次生成的参数及消耗的零件快照。

## 6. 开发路线图 (Milestones)

- **Phase 1 (基础转化)**：实现图片上传、色块化算法、输出 Excel 清单（忽略库存）。
- **Phase 2 (说明书生成)**：接入 PDF 渲染引擎，实现分层 6 视图输出。
- **Phase 3 (库存系统)**：搭建 SQLite 数据库，实现库存 CRUD 及 Excel 导入/导出。
- **Phase 4 (视觉识别)**：集成 YOLO 模型，实现拍照辅助录入颜色。
- **Phase 5 (约束算法)**：实现“库存约束拼搭”及三种缺货策略逻辑。
- **Phase 6 (跨端与云)**：封装 Web 接口，部署云端计算排队任务（如 Celery）。

---

## 7. 非功能性需求 (NFRs)

- **性能**：算法主循环需使用 Numpy 向量化操作，确保 48x48 颗粒（2304 片）运算在本地 60s 内完成。
- **隐私**：本地计算模式下，图片不上传服务器；云端计算模式需在用户授权后加密传输，计算完毕立即删除临时文件。
- **国际化**：界面支持中英文切换（因面向 GitHub 全球用户）。

---

## 8. 注意 (Caution)

1. **6 视图生成**：乐高拼搭的“分层”是指物理层（自下而上逐层）。
2. **零件形态匹配**：库存匹配时，允许用“2 块 1x2 板”替代“1 块 1x4 板”。
3. **零件高度可能超过1层**：整体拼搭出来的积木不一定会是完美的长方体，而更可能是一个有分层的有各种凹凸的整体。
4. **关于凹凸**：需要引入ai识别然后用户微调的图中的重点，重点部分可以设计为突出部分。
